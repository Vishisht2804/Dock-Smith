# Docksmith

Docksmith is a small, educational container build and execution system written
in Python. It demonstrates the core ideas behind a container workflow without a
daemon or registry:

1. Parse a `Docksmithfile`.
2. Build deterministic filesystem layers from a local base image.
3. Store image manifests, layers, and build-cache entries locally.
4. Reassemble the layers into a temporary root filesystem.
5. Run a command inside a Linux mount namespace and `chroot`.

Docksmith is a learning project and is **not** intended to replace Docker,
Podman, containerd, or a production container runtime.

## Features

- Dockerfile-like instructions: `FROM`, `COPY`, `RUN`, `WORKDIR`, `ENV`, and
  `CMD`.
- Content-addressed SHA-256 image layers.
- Deterministic layer archives for repeatable builds.
- Cache reuse for `COPY` and `RUN` steps.
- Local image listing and removal.
- Runtime command and environment-variable overrides.
- Filesystem isolation using Linux primitives.

## Requirements

- Python 3.8 or newer.
- Linux with permission to use `fork`, `unshare`, and `chroot`.
- A local base image imported from a Docker image archive.

The build and run paths use Linux-specific functionality. On Windows, use
**WSL2** or another Linux virtual machine. The repository's bundled
`alpine_3.18.tar` can be used as a base image archive if it is available in the
working tree.

No third-party Python packages are required.

## Quick start

Run these commands from the repository root in Linux or WSL2:

```bash
# Import the Alpine base image into ~/.docksmith
python3 setup_base_image.py alpine_3.18.tar alpine 3.18

# Build the sample application
python3 docksmith.py build -t sampleapp:latest sampleapp

# List locally stored images
python3 docksmith.py images

# Run the image's default CMD
sudo python3 docksmith.py run sampleapp:latest
```

Depending on the Linux user and system configuration, `RUN`, `chroot`, and
namespace operations may require elevated privileges. Run the complete command
with `sudo` when necessary, or configure the host to permit the required
operations.

## Importing a base image

Docksmith does not pull images from registries. Import a Docker-saved image
archive into the local store:

```bash
docker pull alpine:3.18
docker save alpine:3.18 -o alpine_3.18.tar
python3 setup_base_image.py alpine_3.18.tar alpine 3.18
```

The import script reads the Docker archive, normalizes its layer metadata, and
writes the image manifest and layers to `~/.docksmith`.

## CLI reference

### Build an image

```bash
python3 docksmith.py build -t NAME:TAG CONTEXT
python3 docksmith.py build --no-cache -t NAME:TAG CONTEXT
```

The context must contain a file named `Docksmithfile`. `--no-cache` disables
cache lookups and cache writes for the build.

### List images

```bash
python3 docksmith.py images
```

### Run an image

```bash
python3 docksmith.py run NAME:TAG
python3 docksmith.py run -e KEY=VALUE NAME:TAG
python3 docksmith.py run NAME:TAG /bin/sh -c "echo hello"
```

The command-line command replaces the image's `CMD`. Repeating `-e` adds
runtime environment overrides; these take precedence over image environment
values.

### Remove an image

```bash
python3 docksmith.py rmi NAME:TAG
```

## Docksmithfile format

The parser supports one instruction per line. Blank lines and lines beginning
with `#` are ignored.

```dockerfile
FROM alpine:3.18
WORKDIR /app
ENV APP_NAME=DocksmithDemo
COPY main.py /app
RUN echo "Build complete for $APP_NAME"
CMD ["/bin/sh", "-c", "echo Hello from $APP_NAME"]
```

Supported instructions:

| Instruction | Description |
| --- | --- |
| `FROM name:tag` | Uses an image already imported into the local store. |
| `COPY src... dest` | Copies files or glob matches from the build context. |
| `RUN command` | Executes the command with `/bin/sh -c` and stores added or modified files as a layer. |
| `WORKDIR path` | Sets the build and runtime working directory. |
| `ENV KEY=VALUE` | Adds or updates an image environment variable. |
| `CMD ["arg", "..."]` | Sets the default command as a JSON array. |

`CMD` must be a JSON array. Image references must use the `name:tag` form.

## Local state

Docksmith stores its state in `~/.docksmith`:

```text
~/.docksmith/
├── images/          # Image manifests
├── layers/          # Content-addressed tar layers
└── cache_index.json # COPY and RUN cache entries
```

Each build assembles the base image layers with new layers generated by
`COPY` and `RUN`. A cache miss invalidates subsequent cache lookups in that
build, matching the usual layer-build behavior.

## Limitations and security

Docksmith intentionally has a limited scope:

- No image pull, push, registry authentication, or OCI registry workflow.
- No multi-stage builds, build arguments, volumes, ports, networking, or
  capabilities.
- No daemon, API server, orchestration, or service supervision.
- The layer diff currently tracks regular files and does not provide complete
  filesystem semantics such as whiteouts, deletions, or metadata preservation.
- Linux isolation is educational and is not a complete container security
  boundary. Do not run untrusted images or commands with elevated privileges.

See [DOCKSMITH_ARCHITECTURE.md](DOCKSMITH_ARCHITECTURE.md) for the detailed
component design, build/run flow, and known limitations.
